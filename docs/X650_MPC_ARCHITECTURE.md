# X650 + 二连杆 MPC 验证范围与接入设计

日期：2026-10-21。状态：用户已选择先实现上层 MPC，再开展全身动力学 NMPC。上层 MPC 的离线数值实现与接口测试已完成；原生 Gazebo/PX4 带臂辨识、闭环接入和八字性能实验尚待执行。本文同时记录已实现范围与后续验证要求。

## 现有接口与论文的区别

项目的已验证 PID + 前馈版本由 PX4 执行位置、速度、姿态、角速度级联控制。上层使用实际机体与关节状态，计算三维机体速度与两关节速度，进行末端位置闭环分配；它是单步有界最小二乘控制，没有预测时域。PX4 参数名中的 `MPC_*` 表示多旋翼位置控制参数，不代表使用模型预测控制。

用户提供的全身 MPC 论文是 Marti-Saumell、Sola 等的 *Full-Body Torque-Level Non-linear Model Predictive Control for Aerial Manipulation*，arXiv:2107.03722v2（2023）。其第 IV 节以浮动基位姿、关节构型及速度为状态，使用整机刚体前向动力学 `H(q) qdd + C(q, qd) = G u`；控制输入是各桨推力与关节力矩。第 VI 节给出 Weighted、Rail 和 Carrot MPC，采用 FDDP 等方法求解滚动时域问题。论文同时讨论计算延迟与状态预测。论文 PDF 由读者另行获取，不随本仓库源码分发。

| 路线 | 优化输入与模型 | 对当前平台的要求 | 可以形成的结论 |
|---|---|---|---|
| 分层全身运动学 MPC | 同时优化机体三维速度和两关节速度；预测末端运动，并加入低层执行响应 | 保留 PX4 PID 与 Gazebo 关节速度接口，识别响应和延迟 | 对现有 PID + 前馈协调器增加预览、预测和时域约束的效果 |
| 全身动力学、推力/力矩级 NMPC | 整机浮动基动力学；优化四个桨推力和两关节力矩 | 新建/验证推力和关节力矩执行接口、完整刚体模型及求解链 | 接近论文的全身动力学控制层级，仍需注明模型、任务和求解器的具体差异 |

建议先完成两条路线共用的模型接入、碰撞与质量检查、传感/时间戳检查、带臂悬停及小幅响应实验。保留 PX4 内环时，算法应明确命名为“带执行器响应预测的分层全身运动学 MPC”，不能称为复现论文的 torque-level NMPC。

## 共用模型与前序验证

原机械臂以 `assets/models/x500_underfold/model.sdf` 为物理依据：杆长 0.30/0.25 m，质量 0.25/0.20 kg，两个关节轴沿机体 +Y；零位第一杆俯仰 150 度，第二杆水平。物理角度范围为 q1 [-60, 30] 度、q2 [-25, 60] 度。原任务软件速度上限为 0.45/0.35 rad/s、指令变化率上限为 0.60/0.60 rad/s²；它们比 SDF 的 2 rad/s 物理上限更严格。物理力矩上限为 10/8 N·m。

X650 原无臂质量为 3.02 kg，加上述机械臂 0.45 kg 和显式假设的安装座 0.025 kg 后为 3.495 kg。新安装位姿从 X650 的碰撞和落地间隙检查确定，不沿用旧机安装坐标。组合模型 v2 把肘部第二连杆沿共同关节轴 +Y 错层 0.04 m，以消除原理想方杆同平面自穿；杆长、连杆质量和局部惯量保留，新增偏移进入正运动学、总质心与惯量计算。记录完整模型、安装偏移、固定部分质心、零位全机质心和惯量、随关节运动的质心变化及动力参数来源。机械臂质量不能重复计入重力补偿。

模型准备后依次验证：

1. 静态几何：机械臂与机身、起落架、桨盘的间隙，零位和任务关节范围的自碰撞，落地间隙。
2. 原生物理：Gazebo/SDF 校验、实际质量/惯量、关节轴和速度方向、传感器/真值坐标，以及不穿透/不爆振。
3. 带臂悬停：更新悬停推力与电机分配，确认关节保持、正常起降、执行器余量和 PX4 参数读回。
4. 小幅响应：在新机上测量机体速度响应与延迟、关节速度执行响应和指令/状态时间戳。原无臂悬停或旧 x500 的参数不能替代本项。
5. 闭环补偿：先保持末端定点并扰动机体，观察关节是否依据实际位置/姿态误差主动补偿，检查关节余量与不可补偿方向。

碰撞和地面间隙结论应限定到实际扫描的关节范围及采样分辨率，不能仅凭单张截图声称全工作空间无碰撞。

## 分层路线的候选 MPC

状态为 `x=[p_W(3), v_W(3), q(2), dq(2)]`；控制为 `u=[v_base_cmd(3), dq_cmd(2)]`。初步可用闭环执行响应模型 `pdot=v`、`vdot=(u_base-v)/tau_base`，关节按实际接口选择速度直接执行或 `dqdot=(u_joint-dq)/tau_joint`。时间常数和纯延迟均需由上述原生实验确定。不能把手工初值标成已辨识参数；若响应需要二阶或轴间耦合模型，应根据预测残差升级模型。

末端位置 `p_tip=p+R*r(q)`，在移位后的上一条预测轨迹各节点线性化。`R` 和角速度来自实际机体反馈；采用短时姿态外推时须记录外推规则及范围。四旋翼的滚转/俯仰不能当成可以任意瞬时执行的自由决策量。

当前数值实现位于 `control_packages/x650_wholebody_v1/x650_wholebody/mpc.py`：15 个节点，第一段采用真实控制周期（例如 0.02 s），后续段为 0.04 s，所以该示例的实际时域为 0.58 s。每个更新构建一次线性时变凝聚凸 QP；对 Hessian 作精确 Cholesky 变量变换后，用 SciPy SLSQP 及解析梯度、线性约束求解。0.20/0.20/0.25 s 的基座响应时间常数仍是未辨识工程初值；关节暂按理想速度接口，未补偿未知通信/状态延迟。

本地 100 步、75 变量的数值计时中，白化后 SLSQP 均为 2 次迭代，求解耗时 p50/p95/max 约 7.73/26.70/63.50 ms，含构建和质量检查的总耗时约 28.63/67.15/211.63 ms。该记录只说明本地数值计算开销，不代表原生闭环或服务器实时性。20 ms 截止并未逐次满足；实际频率须根据服务器上的仿真时间推进、完整回调与发送开销选择，不能据此宣称 50 Hz 已实时通过。数值证据位于 `generated/x650_mpc_local_qp_timing_whitened_20261021.json`。

恢复工作后，新增可复现计时入口 `control_packages/x650_wholebody_v1/tests/benchmark_timing.py`，改为显式从哈希绑定的 v2 准备报告载入模型。相同 100 步、75 变量的本地记录中，默认线程环境总计算 p50/p95/max 为 26.63/42.86/65.73 ms；新进程在导入 NumPy/SciPy 前请求单 BLAS 线程后为 18.36/24.47/52.82 ms，单独求解为 3.36/7.64/35.29 ms。两次全部为 2 次 SLSQP 迭代，primal < 3e-16、KKT stationarity < 5e-16。原始记录分别是 `generated/x650_mpc_timing_bound_default_20261021.json` 和 `generated/x650_mpc_timing_bound_single_20261021.json`，不覆盖旧记录。这仍是本地数值时延测试，且未包含 ROS/MAVLink/前馈和日志开销，不能作为服务器 50 Hz 通过证据。

代价以预览节点的三维末端位置误差为主，加入末端速度误差、基座/关节名义参考偏差、输入和输入变化项。保留原任务的可比速度、指令加速度及关节角度限制，并检查预测末端的制动可行性。飞机/机械臂 80%/20% 只可作为相同的名义参考或偏好，实时优化后的纠偏分配由末端误差、模型、权重及约束决定。任务是末端三维位置跟踪，不宣称二自由度机械臂可以单独完成任意六维末端位姿任务。

机体运动惯性前馈应使用同一显式机械臂参数与新总质量，并在两组采用同一计算方法和限幅。当前 p/v/a 接口只注入平动加速度前馈，反作用力矩只能作为诊断记录。修改前馈算法时应作为独立因素报告。

## 执行、延迟和失败记录

记录状态采样、控制计算、发送和实际接收的仿真时间戳，区分墙钟耗时与仿真时长。用已发送命令的历史队列预测到预期执行时刻；延迟队列覆盖的预测首段不能被优化器当成仍可修改的控制。参考按同一绝对仿真时间预览，不对结果事后移相。

每次执行滚动序列第一项并用最新反馈重算。求解失败或超时可移位上一条可行序列，但必须重新检查当前状态和约束；连续失败时停止任务并正常降落。若实际切回其他控制器，应明确记录时段，不能把静默回退的数据算作 MPC 成功。

当前实现的 `failure_policy="raise"` 是默认策略；可选 `shift` 会重新验证上一条移位计划并明确记录 fallback。`solve_budget_ms=20` 当前只记录超预算，不能中断正在运行的 SLSQP，也不会自动拒绝超时但可行的返回值；runner 需要检查完整计算结束后的仿真时间与状态年龄。状态/命令延迟队列属于待接入部分，当前元数据明确 `state_delay_compensated=false`、`command_delay_compensated=false`。

PX4 参考编码还需保持原接口的误差语义：上层若输出目标执行速度 `u_base`，不能在位置参考之外再重复叠加 PX4 位置 P 反馈。对应的机体位置、速度、加速度参考应由同一状态快照和已读回的实际 PX4 增益构造。

## 原生 runner 的具体接入建议

首轮保持单一仿真时间轴和同步 0.02 s 目标周期，并在导入 NumPy/SciPy 前请求 `OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=1`、`MKL_NUM_THREADS=1`，再在服务器实际环境测量完整计算时延。先用地面状态检验回调、时间戳与发送链；模型和参数门禁通过后，才进行带臂起飞。

若完整计算超出每个 20 ms 仿真周期的墙钟预算，初次验证可以为 PID 和 MPC 两组采用同样的较低 Gazebo `real_time_factor`，保持物理积分步长、轨迹仿真时间及内环参数一致。例如实际 RTF=0.20 时，每个 20 ms 仿真周期约有 100 ms 墙钟预算。必须保存 world 配置/哈希及实际 RTF，并相应调整起飞、稳定门槛等墙钟超时；这会降低运行速度，不构成已经具备实机实时性的证据。

每步记录反馈/关节时间戳、读取、计算开始/结束、发送时刻和实际 `control_dt_s`，还要检查返回后状态年龄、漏发与 fallback。`max_dt_s=0.05` 的异常门槛不能替代 50 Hz 发送间隔分布的验证。

如果以后拆成较低频率的 solver 和 50 Hz sender，sender 必须持有带绝对仿真时刻的计划、使用最新状态重新构造编码/前馈，并把实际已发输入回灌预测。`ControlCommand` 封存原计算时刻的真值快照，不能把旧 command 反复配上新的 PX4 状态就称为反馈已更新。还须统一每 0.02 s 实际发送的变化率与预测模型：直接把 20 Hz 的 `step(dt=0.05)` 结果以较大跳变在 50 Hz 发出，或把 0.04 s 预测节点加速为 0.02 s 执行，都会改变约束语义。引入插值/速率限制器时，预测也必须包含同样的执行规则。当前代码尚未提供这一整套异步执行机制，第一轮不依赖它开展正式比较。

## 公平对照与交付证据

原生响应辨识入口已实现为 `scripts/identify_x650_upper_response.py --train <run1> --holdout <run2> --output <新目录>`，真实数据验收尚待执行。它对原始 `sim_s` 命令事件与 `truth_stamp_s` 测量时间进行不等间隔 ZOH 传播，只拟合 train 的三个时间常数；holdout 不参与参数选择，也不允许与 train 是相同或仅重新存储的测量。前后 MC/MPC 参数及两次模型/PID/airframe 来源必须一致。固定的激励、RMSE、峰值、偏差、跨轴及未建模延迟拒绝判据写入输出；它们是本次预先声明的工程容差，不是模型真实阶次或全工况最优性的证明。

成功输出 `response_model.json` 与哈希绑定原始文件的 `response_identification.json` stage evidence；失败仍保存明确 `passed=false` 证据，不自动松动阈值。使用模型前，runner 还须验证输出的实际 PID 哈希与当前读回值一致，且配置的响应文件就是 stage evidence 绑定的那份文件。当前只标定折叠配置下的小幅基座速度响应，关节/角动态和快速八字性能保持独立验证范围。详细阈值与服务器现成依赖调用示例见控制包 README。

两组必须使用同一 X650 + 臂模型、同一 PID 内环、同一机械臂执行器、同一前馈、同一反馈来源/延迟、相同初始门槛和任务边界。新机的 PID 至少先通过小幅响应验证；旧 x500 已选出的参数不能称为 X650 已充分整定的最优 PID。若本轮只做接口验证，应如此标注。

沿用原八字：世界 XZ 平面，X 幅值 ±0.25 m、Z 幅值 ±0.10 m，含原平滑起止段；普通 12 s/圈、快速 8 s/圈，两圈。普通闭环通过后再进入快速任务。调参/辨识工况和最终比较任务应分开，选定后冻结参数并读回记录；不能根据最终比较曲线反复挑选最有利的版本再宣称独立验证。

至少交付完整起飞至降落的视频、世界坐标目标/实际末端轨迹、未经事后配准的末端误差、机体与关节状态/指令、执行器饱和与约束余量、求解耗时/失败率、模型和源码哈希、飞行前后参数快照、PX4 ULog 及原始 CSV/ROS bag。轨迹跟踪主要报告同步时间误差；若另报几何路径距离，应单独命名。

视频可以由实际 Gazebo 记录状态回放生成，但必须标明状态回放，并说明未记录的关节或桨叶角度。离线数值测试、日志重放和真实 PX4/Gazebo 闭环运行应分别记录。
