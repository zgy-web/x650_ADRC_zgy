# X650 NMPC 第一版实施依据

日期：2026-10-27。本文记录实现选择与验收边界，不是 NMPC 仿真通过报告。现有 MPC 保持独立可调用接口；本轮不重新整定其参数，不继续扩大模型偏差测试。

## 1. 两种 NMPC 对应不同实验问题

| 项目 | A：同执行接口的上层 NMPC | B：全身动力学 NMPC |
|---|---|---|
| 要回答的问题 | 相同传感、控制权和执行链下，非线性优化能否改善当前 MPC 的计划？ | 直接利用机体与机械臂动力学耦合，能否改善动态性能？ |
| 控制输入 | 三轴机体逻辑速度与两个关节逻辑速度，共 5 维 | 例如四旋翼推力与两个关节力矩，共 6 维；或明确建模后的舵机参考 |
| 预测对象 | PX4 闭环响应、姿态与末端几何、TS20 接口动态 | 浮动基体、多刚体耦合、旋翼及关节执行动态 |
| 执行端 | 沿用当前 PX4 PVA 编码和 TS20 MIT 参考桥接 | 新增下层执行映射、状态估计和接管链，需要独立验证 |
| 与当前 MPC 的对照 | 可以把主要差别限制在求解方法 | 同时改变模型、输入和控制架构，不能把收益全归因于“非线性” |

已有路线文档选择先 A 后 B；本轮最终执行范围以用户最新选择为准。A 已经将机体和关节共同用于末端任务，可以称为全身协同的上层 NMPC，但不能称为旋翼推力／关节力矩级全身 NMPC。

Lunni 等明确采用上层机体／关节速度输入，动力学部分采用积分模型，非线性来自任务和约束；低层 PID 负责跟踪。因此，“NMPC”不要求第一版就更换成力矩输入。该论文实际实验为 ODROID XU3 上 2 Hz、10 节点、5 秒时域，不能照搬为本机实时性能保证。[论文机构入口](https://hdl.handle.net/2117/108724)，本地 PDF 第 3、6 页。

## 2. 第一版同接口模型

保留现有控制契约中的 ENU 世界系、FLU 机体系、两关节方向及实际命令历史。输入为

\[
u=[v_{B,x}^{cmd},v_{B,y}^{cmd},v_{B,z}^{cmd},\dot q_1^{cmd},\dot q_2^{cmd}]^\top.
\]

状态至少包含机体位置、闭环速度／水平加速度状态、旋转与角速度观测、实际关节 \(q,\dot q\)、MIT 未量化位置参考 \(r\)，以及已经发送的延迟命令／数据包历史。历史与总线相位是预测上下文，不能用最新 \(q\) 每轮重置 \(r\) 来代替。固定偏航与现有姿态预测关系仍按原模型处理，不新增偏航控制权。

末端位置在每个候选节点通过完整几何计算：

\[
p_E=p_B+R_B\,r_E(q).
\]

采用当前已验收的水平二阶、垂直一阶闭环响应；这属于等效内环模型。更新每个候选的关节传播和姿态／末端输出后，评价真实非线性残差，而非仅评价在旧中心固定好的仿射末端残差。

沿用的条件 TS20 模型为

\[
\dot q=v,\qquad
\bar J\dot v=u_d-K_pq-(\bar b+K_d)v-\bar o-f(v),
\]

其中 \(u_d\) 来自 5 ms 总线网格上的量化 MIT 数据包及一次有效接口延迟。静止时还包含起动阈值与零速切换事件。当前候选配置为 \(K_p=6,K_d=0.25\)，不能误用旧文档早期的 \(K_d=3276/32768\)。完整系数、时间和哈希必须来自调用方配置，不能在 NMPC 内另写一套近似常量。

现有模型的 \(\bar J,\bar b\) 等是归一化接口参数。它们不具备已验证的关节轴端 N·m 尺度，不能直接把 URDF 的 kg·m² 加到 \(\bar J\) 上。24 V 和当前连杆负载仍是条件仿真；用户确认硬件型号与供电，不等于辨识模型完成了带载实测。[TS20 固定源版本](https://github.com/ZHUOZHUOO/TS20/tree/a97ef4f227ab778f9efdf86ff93ee309d7d35a22/models/ts20_50)。

## 3. 新算法不能只是旧恢复分支改名

当前 C++ MPC 已有局部 QP、可信中心恢复、最多三次控制子问题，以及非线性候选与节点之间包络检查。这些步骤的目的是恢复局部可行性，不足以单独构成新的 NMPC 方法。

新的同接口 NMPC 应明确实现下列优化问题：

\[
\min_U\;J(U;x_k)=\sum_{i=1}^{N}\|p_{E,i}(U)-p_{E,i}^{ref}\|_{Q_E}^2
+\text{同基线的机体、关节、输入与增量代价},
\]

\[
x_{i+1}=F(x_i,u_i;\text{实际历史、MIT 相位}),\qquad g_i(x_i,u_i)\le0.
\]

这只是结构表达，具体项与归一化需逐项绑定原配置；不能因为写成上式就悄悄增加终端权重、姿态任务或新的分配比例。初始公平对照保留当前 15 节点和名义 40 ms 节点间隔，实际首步仍遵守既有时间契约。

若采用本项目 C++ 序列二次近似，应保存每轮真实 \(J(U)\)、步长、可行性、接受／拒绝原因。候选重新经过完整非线性传播，接受准则基于真实目标或明确的可行性准则；在当前状态下重新线性化，不反复解同一个固定 QP。热启动来自已执行历史和移位计划；恢复中心、线搜索试点不写入实际命令历史。

TS20 的量化和静摩擦使原始映射非光滑，现有滑移支路灵敏度也明确不是完整事件映射的导数。若暂时沿用该灵敏度，应称为“使用事件模型验证的序列二次近似上层 NMPC”，记录代理导数的适用范围；不能声称是原始非光滑模型的精确梯度法。另一条路线是建立可微优化代理、以原事件模型作最终验证，但需要单独验证模型差异，不能静默替换。

连续关节速度内界仍为 0.42／0.32 rad/s，保留已确定的位置、输入、参考积分、停止与节点间检查，不加入松弛变量。NMPC 数值收敛不等于可发布；所有下发候选仍经过独立执行有效性检查。

CasADi 是建模、微分与求解器接口工具，不会自动把现有任意 C++ 分支程序转换为可微模型。[CasADi 官方文档](https://web.casadi.org/docs/)。IPOPT 面向一般非线性规划，目标和约束应二阶连续可微。[IPOPT 官方说明](https://www.coin-or.org/Ipopt/)。acados 提供结构化 OCP 求解、SQP 类方法、积分和 C 代码部署能力；实际 Orin 时间需要测量。[acados 官方文档](https://docs.acados.org/)。

推荐先把 A 的控制接口、非线性评价和离线数值证据做实，再决定是否引入 acados。若直接选择 B，则先建立可验证的刚体动力学与输入映射，再比较求解器。两条路线都不需要把 Python 放回定周期下发路径。

## 5. 全身动力学 NMPC 的状态和输入边界

对四旋翼加两关节，广义配置为 \(Q=(p_B,R_B,q)\)，广义速度 \(\nu=(v_B,\omega_B,\dot q)\in\mathbb R^8\)。使用四元数存旋转时配置有 9 个数，状态有 17 个数，但独立状态维数为 16；姿态应在旋转流形上处理，不能把四元数四维误差当四个独立转动自由度。

自由空间动力学可以写为

\[
M(Q)\dot\nu+h(Q,\nu)=G(Q)u,
\qquad u=[f_1,f_2,f_3,f_4,\tau_1,\tau_2]^\top.
\]

\(M\) 的机体与关节交叉块决定耦合，\(h\) 包含科氏、离心和重力作用；\(G\) 含桨位置、推力方向、反扭矩系数和关节驱动。计算可采用递归刚体算法，避免显式求逆。前向运动学给出末端任务。若用舵机参考代替 \(\tau\)，还需将执行器内部状态和闭环动态加入模型，不能写上 \(\tau\) 就假定驱动可直接实现它。

该结构对应 Martí-Saumell 等论文第 IV 节，而其全身方法主要在仿真中验证。[Full-Body Torque-Level NMPC](https://arxiv.org/abs/2107.03722)。后续 Borinot 平台实际使用可变阻抗关节执行器，以及经台架标定的推力与电压映射；其机载案例采用 35 节点、20 ms 节点间隔。这些硬件能力不是我们的 TS20 和电调自动具备的条件。[Borinot](https://arxiv.org/abs/2307.14686)。

本机 B 阶段至少需要：正确导入各刚体惯量与关节轴、静态重力和动量守恒检查、机体—摆臂反作用检查、旋翼推力映射、TS20 力矩／参考执行尺度、饱和与推力分配、PX4 接管退出。MIT 的 `tau_ff` 字段证明接口有该分量，不证明轴端力矩标定正确；目前仓库明确标记 `physical_torque_scale_identified=false`。可先做标注清楚的理想力矩仿真研究，但应与可迁移执行器实验分开。

## 6. 可调用接口与第一批验收

MPC 与 NMPC 共用状态／目标／实际执行历史的输入结构，返回候选计划、首指令和诊断。核心不打开 ROS、Gazebo 或硬件连接。外层适配器负责坐标编码、时间、期望与实际消费反馈，控制器只在实际发布或消费契约满足后提交历史。NMPC 增加的内部试探计划不改变该契约。

保留三个分层证据：

1. **接口与数值**：MPC 封装前后同输入同输出；NMPC 非线性目标和梯度／代理方向检查；候选接受与拒绝、历史提交回滚；无效时间、非法输入、超时分支。
2. **离线与软件回放**：保持、平滑换向、边界、旧外扰记录；报告目标值、可行性、迭代数和整步时间。离线结果不能作为 Gazebo 已闭环证据，也不能用历史实际状态拼出新算法的“物理效果”。
3. **新的物理闭环**：保持完整窗口和实际消费／退出审计通过后，再普通八字，最后快速八字。每次保存明确后端身份、冻结参数和原时轴误差；只因求解器返回 success 不能跳过验收。

首轮对照沿用相同 PX4 内环、TS20 条件模型、任务与硬界，记录算法求解时间、实际下发间隔和计划年龄三个不同量。服务器结果不是 Orin 实时保证；后续在实际 Orin 上运行相同调用接口进行处理器在环测试。

本说明核对了本地 Lunni PDF 第 2–6 页、全身 NMPC PDF 第 4–7 页、Borinot 第 9 页，以及仓库当前 `mpc_core.hpp`、`mpc_core.cpp`、`ts20_prediction.py` 和执行器配置。关键公式页已渲染复核。后续实现报告应单独列出实际完成范围，不能把本文列出的候选路线全部写成已实现。

## 7. 对复用 ABI 4 Core 生成候选的具体审查

在固定的一份 `StepInput` 与已提交 `Memory` 下，可将 Core 用作局部候选生成器：每次恢复原已提交状态，只替换数值热启动 `plan/plan_h/plan_t`；求解后的试探历史不用于下一次优化迭代。外层以完整非线性目标选取安全且改进的候选。这个结构可作为有界重线性化研究原型，但它缺少一般线搜索和非光滑模型的收敛证明，不能标成已求得完整 NLP 最优解。

实现时有以下具体约束：

- **保持同一个目标函数。** 六项应逐节点乘实际 `h[i]`。前两项使用完整非线性末端位置／速度；随后是机体位置、实际关节位置、按速度上限归一化的输入偏差、按 `acceleration_limit*h[i]` 归一化的输入增量。首节点的增量以前一条实际采用的指令为基准。`Diagnostics.objective` 是局部仿射残差目标，不适合作为不同线性化中心之间的真实目标比较。
- **补查真实停止余量。** 当前 Core 普通成功路径主要通过线性化停止行检查；`stopping_violation` 对真实传播节点的复核在 `recovery_triggered` 分支中执行。新外层若声称每个入选候选满足真实停止要求，应对所有候选计算 `q + reserve*dq`，其中 `reserve=joint_velocity_limit/(2*joint_acceleration_limit)+max_dt+command_hold_s+source_age`，用原关节边界与原容差验收。这是显式验证既有预测要求，不应描述成已具备实际物理停止距离保证。
- **保存选中的完整结果和提交状态。** 后续试探无改善或失败时，返回最佳有效候选对应的命令、诊断与下一状态；不能返回第一次命令却提交最后一次试探的历史。一次控制调用最多增加一次采用记录，内部迭代不会推进控制时间或总线相位。
- **严格区分不可行、停滞和超时。** 没有一个当前状态下的新有效候选时，不得直接沿用上一周期的计划。量化平台上的“目标无下降”不表示达到 KKT 驻点。用明确的绝对加相对阈值判定数值改善，并保留所有候选目标及终止原因。
- **总预算不可被内层重新计时掩盖。** Core 每次独立执行其 50 ms 预算；外层必须另计全部候选调用、目标评价和复制耗时。即使已经找到好候选，超过总有效时间仍不得作为在线可发布结果。最初离线原型如用更大研究预算，须显式记录，不能继承当前 25 Hz 物理验收结论。
- **约束名称应准确。** 原末端输出使用等效闭环姿态预测，不是完整机体动力学；现有候选检查也不是对所有机体状态的独立连续安全证明。报告必须逐项列出实际检查的关节、输入、参考、保持与时效条件。

有辨别力的测试应包括：一次迭代与原 Core 的数值一致性；非等距首步下六项独立目标复算；旋转中的末端速度项；重复迭代的实际历史与参考不变；末次试探失败或无改善后选回正确最佳候选及其状态；总预算超时后完整回滚；所有候选的实际停止、节点间及 160 ms 首指令保持检查；至少一个固定状态下真实目标下降且候选实际变化的例子。后者若未观察到，结果应写为“原型通过接口与拒绝行为测试，尚未展示额外优化收益”。
