# X650 MPC：节点间硬约束恢复

本次按用户明确选择，**不增加松弛变量 s**。两个关节的预测速度内界仍为 **±0.42／±0.32 rad/s**，角度内界、原数值容差和最终候选检查保持不变。新增处理的对象是原第 429 次固定输入所暴露的节点间速度极值，以及连续优化指令经过舵机编码后的差异。

本页说明算法与证据范围；具体软件验证结果见[本次验证记录](validation/cpp_interval_hard_20261026/README.md)。固定历史输入的计算验证不能代替新的 PX4／Gazebo 闭环受扰实验，也不能证明真机安全或最坏计算时延。

## 为什么只限制预测节点还不够

QP 原来约束离散时刻的关节角度与速度，但 TS20 模型在两节点之间仍会运动。原失败输入的节点速度全部符合内界，区间内却出现 `−0.420047472385 rad/s` 的速度极值，因此最终完整预测检查拒绝了候选。

此外，未来 MIT 速度参考按 `1/512 rad/s` 分档，位置参考按 `2π/2^24 rad` 分档。连续决策量的小幅变化经过编码后可能跨档；只用连续局部梯度贴住边界，并不保证编码后的完整模型同样贴住边界。

## 恢复流程

1. 按原流程求解并生成真实格式的候选 MIT 指令，运行完整 TS20 预测。
2. 若完整预测出现 q／dq 内界违反，读取实际违规极值，并补入同一关节、同一状态量和违规方向上的其他局部风险点。
3. 保留原积分网格，沿原积分子段旁路计算这些时刻的状态；不得通过加入新的积分边界改变原预测结果。旁路计算与原生核的边界状态、完整包络及子步数逐项核对后才可使用。
4. 以本次候选为新的线性化中心，重新计算所有旧点与新增点的约束，追加到原 QP。旧点保留，避免修复一个峰值后丢掉另一个峰值。
5. 再次求解后重新编码、完整传播并检查整个时域。只有全部原检查通过才提交内部状态与候选；超预算、无解或完整预测仍违界时拒绝并回滚。

对时刻 `t*` 的状态量 `y`，局部形式为：

\[
\widehat y(t^*,z)=y(t^*,\bar z)+g(t^*)^\top(z-\bar z),
\]

其中 `z` 是原 75 维归一化控制序列，`z̄` 是本轮线性化中心。新增约束仍是硬约束；没有给速度边界右端增加可以付罚分的 s。

风险点筛选使用原 0.02 信赖域下的局部支持范围：

\[
\Delta(t^*)=0.02\sum_{j\in\text{该关节控制列}}|g_j(t^*)|.
\]

该范围用于筛选需要补约束的位置，不是对完整非线性系统误差的证明。最终仍依赖原生完整候选检查。

## 编码余项进入硬约束

对未来包 p，位置／速度取整形成等效驱动力误差：

\[
e_p(z)=k_p(q_p^{\rm enc}-q_p^{\rm cont})+
k_d(v_p^{\rm enc}-v_p^{\rm cont}),\qquad
|e_p(z)|\le\epsilon=\tfrac12(k_p\Delta_q+k_d\Delta_v).
\]

中心包的误差 `e_p(z̄)` 是已知值，不能再次当成零。设固定滑动线性模型中该包对状态时刻 t* 的响应系数为 κp，则相对中心的编码余项满足：

\[
\delta_-=-\epsilon\sum_p|\kappa_p|-\sum_p\kappa_pe_p(\bar z),
\qquad
\delta_+=+\epsilon\sum_p|\kappa_p|-\sum_p\kappa_pe_p(\bar z).
\]

新增行要求：

\[
y_{\min}-\delta_-\le\widehat y(t^*,z)
\le y_{\max}-\delta_+.
\]

这是利用已知编码分辨率向内预留的规划余量，没有放宽 `y_min/y_max`，也没有让优化器通过增加 s 购买越界。该推导只约束固定滑动模型的编码余项，不能覆盖所有摩擦变化与模式切换；完整 TS20 候选检查仍是最终准入条件。

## 保持的边界和预算

| 项目 | 本次规则 |
|---|---|
| 决策维数 | 原 15 节点 × 5 控制量，75 维 |
| 松弛变量 | 不增加 |
| dq1／dq2 状态内界 | ±0.42／±0.32 rad/s |
| q1／q2 状态内界 | [−0.7497, 0.4497]／[−0.3497, 0.8497] rad |
| 原候选数值容差 | 2e−7 |
| 初始关节信赖域 | 0.02 |
| 正式控制 QP | 每次调用最多 3 次 |
| 原辅助中心投影 | 最多 1 次 |
| 总计算准入门槛 | 原 50 ms；不是操作系统硬实时保证 |
| 累计新增点 | 最多 512 个，超出则拒绝 |
| 指令与历史 | 使用原实际命令历史、编码、时序；不伪造已执行状态 |

Core ABI 升至 3，以显式区分新增的诊断结构。QP／模型库的接口不因此改变；实际运行必须绑定匹配的工作进程、核心库与新验收记录，不能沿用旧 ABI 2 的飞行证书。

## 复现与审计

`scripts/run_x650_interval_regression.py` 对每条历史输入恢复其自己的完整原 Memory，分别调用新核心；随后独立审计 QP 原行、新增行、编码包、状态提交和候选包络，并使用原 TS20 动态库在独立重建的原网格上再次传播。

这类验证有意不把第 429 次新输出接到历史第 430 次状态：后者原本并不存在。它回答“相同失败输入能否产生满足原约束的新候选”，新的连续闭环效果必须另外实测。

原失败、各开发版本的拒绝与最终验证结果均保留。未触发恢复的正常路径另与旧版逐元素比较，防止为局部修复无意改变其他控制行为。
