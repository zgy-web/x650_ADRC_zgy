# 已白化 QP 的单位矩阵初始化优化

本次只消除已知单位 Hessian 的重复 Cholesky 分解及三角求解。白化坐标、目标函数、约束、活动集迭代、原始行收敛标准、KKT 检查和非线性候选验收保持不变。专用入口逐元素要求精确单位矩阵；一般 Hessian 继续使用原入口。

这是 **局部数值实现优化，不是完整保持通过，也不是已解决全部时序问题**。服务器生产库在本次 scratch 比较期间未被替换。

## 原始故障输入与实测

先按真实 LiveStart 和原 CDR 顺序重放 hold25 的 1056 条输入，仅为离线执行重设 monotonic 寿命基准，实际状态、模型时间、历史、参数不变。20 ms 绝对节拍、初始空闲 0.5 s、自然 GC 保留，未创建执行器发布端。1056 条均返回成功，指令与原记录的最大绝对差为 0。然后在尾部 1054–1056 次求解捕获完整原 QP。

| 检查 | 实际结果 |
|---|---|
| 三个真实 QP 的前后解 | 逐字节一致，目标值和原质量字段一致 |
| 原始行与独立 KKT 复核 | 通过；未放宽门限 |
| 新 C++ 等价与严格入口测试 | CTest 1/1 通过 |
| 现有 native 数值单测 | 21/21 通过，包含 hold16 的旧提前收敛回归 |
| 1055 QP 的 20 ms 配对计时中位数 | 2.574 → 2.163 ms，约节省 0.411 ms |
| 1056 QP 的 20 ms 配对计时中位数 | 3.341 → 2.941 ms，约节省 0.400 ms |

新旧库交替顺序测试，在相同 CPU mask 下分别记录墙钟、线程 CPU 和实际 CPU 编号。完整配对样本、冷启动样本及频率观察保存在 [`comparison.json`](comparison.json)。冷启动只有三个样本，不能将较大收益外推为长期保证。该局部收益不足以证明覆盖 hold25 的约 2.3 ms 首次错槽缺口。
