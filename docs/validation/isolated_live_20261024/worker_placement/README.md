# Worker 线程分配与正常关闭的软件验证

2026-10-24，在服务器独立 ROS 域 217 内完成了一次真实 ROS 软件验证，结果通过。测试创建了真实 DDS 实体和单线程 executor，复用生产补丁中的线程分配、CPU 观测及信号停止 helper。测试没有运行 MPC 求解、Gazebo 或 PX4，也没有发布任何控制指令；这份记录不是完整末端保持或飞行验收结果。

Worker 的总 CPU 集合仍为 `[87, 89, 91, 97]`，主执行线程固定使用 CPU 87，辅助线程使用 `[89, 91, 97]`。绑定完成、READY、测试活动开始及最终关闭前四个阶段都观察到相同的 11 个线程，TID、启动时刻及角色对应的 CPU 集合一致。6 次真实 executor 定时回调的开始与结束均通过主线程身份、单核亲和性及实际 CPU 87 核验。

测试向本次创建的子进程发送 SIGINT。信号只请求主循环停止；最终线程身份检查发生在 ROS Context 仍有效时，随后关闭 executor、节点和 Context。子进程退出码为 0，测试结束没有留下该子进程。这验证了正常停止时不会先销毁 DDS 线程，再错误地把线程消失判为角色漂移。

本次动态交接检查耗时为 **2.680751 ms 墙钟时间、2.656607 ms 本线程 CPU 时间**。交接检查只读取当前 `/proc` 身份与 CPU 集合，并与地面阶段已缓存的证据比较；静态 JSON、helper 源码哈希核验前移到地面，交接记录的文件写入延后到关闭阶段。这个单次测量不代表最坏耗时，也不能证明已经解决 hold25 的指令过期问题。

阶段快照不能排除两次检查之间出现又消失的短命辅助线程；回调开始、结束两个 CPU 样本也不是连续迁核观测。本测试结合了主线程单核亲和性检查，但不作所有辅助线程全程独占的声明。

`manifest.json` 逐项记录了服务器原路径、字节数、SHA-256，以及本地副本核验结果。四个完整原件合计 28,333 字节：

- `report.json`：父进程验证结果、动态交接检查、子进程完整结果与源文件哈希。
- `ready.json`：READY 阶段线程身份与分配原件。
- `child_final.json`：最终阶段与六次回调原件。
- `child.log`：原始日志，本次为空文件。

本地单元测试另已通过 ROS package 77 项、资源验收 9 项、监督生命周期 7 项、地面准备 7 项和 worker 时序验收 6 项。独立源码审查已通过。下一次完整末端保持仍需在最终部署源码与参数绑定下重新验收。
