## 第二、三次尝试与工具修复

第二次已确认正放和机头朝上两面。Windows 进度文件替换发生 `PermissionError`，导致旧版监视线程中断；同时串口出现密集 NUL/二进制乱码，来源未确定，不能据此诊断 IMU 损坏。操作者重启飞控后，确认参数仍为原值。修复后，命令发送前必须成功保存意图；发送后偶发进度文件占用不再打断串口监视，二进制异常明确标记且不能通过完整采集判定。

第三次只发送一次校准命令，六面均有实际完成消息，收到 PX4 成功消息并回读 18 项新参数。过程中发生 3 次进度文件保存冲突，修复后的工具保持监视和内存页面更新直至完成；这次未检测到密集二进制异常。随后取得两段独立静置记录，分别在校准后和重启后采集，均不通过偏置验收。

第二次原始二进制流与完整控制台留在本地，其 SHA256 载于清单；第三次保存了实际执行源码、原始 ASCII/ANSI 校准流和参数前后值。所有完整控制台的哈希已在本机核验；公开归档不包含 `ver all` 的机板唯一序列信息。

## 新参数质量不通过的证据

第三次第一套传感器的各面平均值推算如下。角度是在静态重力主导假设下，平均向量相对对应正负坐标轴的夹角；不是外部倾角仪测量，不能作为单独故障判定。

| 面 | 平均向量，m/s² | 推算偏离目标轴 |
| --- | --- | --- |
| 正放 | [0.568, −0.569, −9.758] | 4.71° |
| 左侧朝下 | [0.166, 9.317, −3.095] | 18.40° |
| 倒置 | [−0.446, −0.788, 9.789] | 5.28° |
| 右侧朝下 | [0.247, −9.621, −1.820] | 10.81° |
| 机头朝下 | [−9.333, −0.126, −3.043] | 18.07° |
| 机头朝上 | [9.494, −0.247, −2.376] | 14.12° |

由此得到的比例系数约为 1.035～1.070。当前固件用相对两面的轴分量计算偏置，并根据三个面的向量求变换矩阵，转换传感器坐标后保存对角缩放项。**方向识别成功不等于姿态误差不会影响校准质量**；本轮非正交摆放是导致新系数偏大的可疑因素，尚非单独排除了所有其他因素的因果证明。[当前固件校准实现](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/src/modules/commander/accelerometer_calibration.cpp)

| 数据段 | 轮数 / 观测跨度 | 三套 IMU 的结果 | 近似恢复运行时偏置补偿前的加速度模长 |
| --- | --- | --- | --- |
| 新校准前，先前重启后的单次探针 | 1 / 单次 | 均未超限 | 9.841 m/s² |
| 新校准后，同一次启动 | 13 / 79.688 s | Z 轴均 13/13 超限 | 10.251～10.264 m/s² |
| 新校准后，再重启 | 13 / 79.640 s | Z 轴均 13/13 超限、偏置 −0.400 | 10.270～10.286 m/s² |
| 恢复原参数后，再重启 | 13 / 79.703 s | 三套全部轴 0/13 超限 | 9.807～9.823 m/s² |

模长采用 `norm(vehicle_acceleration.xyz + 主估计器 accel_bias)` 近似计算。固件的 `vehicle_acceleration` 已减去运行时偏置并低通滤波，不能把它直接当作独立校准观测；以上相加只是静止条件下的近似，各字段依次读取而非严格同步。复算检查了轮内主估计器和加速度计 ID 一致。[当前固件加速度发布实现](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/src/modules/sensors/vehicle_acceleration/VehicleAcceleration.cpp)

偏置门限按 `abs(bias) > 0.75 × bias_limit + 3 × sqrt(variance)` 逐轴复算，字段来自 NSH 有限精度输出。新参数重启后的 Z 轴门限约为 0.309～0.325 m/s²，明显小于 0.400，不属于舍入导致的边界差异。[固件预检公式](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/src/modules/commander/HealthAndArmingChecks/checks/estimatorCheck.cpp)

最初长时间运行时的 X/Y 偏置接近 ±0.4，但在第三次新校准之前，单纯重启且保留原参数就已出现小偏置。因此不能把任何重启后的改善直接归功于六面校准。恢复后观测支持继续使用原基线；最初长时间偏置异常的根因仍未证明，后续应以更长静置、温度变化及实际运行状态检查，不再自动重复校准。
