## float32 输入差异单列

PX4 消息中的机体状态使用 float32，原仿真快照主要为 double。量化后输入已经改变，因此不能套用“同一输入必须一致”的结论。相对原 double 输入重新求得输出的逐轴最大绝对差为：

| 输出轴 | 最大绝对差 | 单位 |
|---|---:|---|
| 飞机 X 速度 | 9.1016e-9 | m/s |
| 飞机 Y 速度 | 8.2507e-9 | m/s |
| 飞机 Z 速度 | 2.6871e-7 | m/s |
| 关节 1 速度 | 2.4812e-8 | rad/s |
| 关节 2 速度 | 4.3280e-7 | rad/s |

711 条保持快照的五维命令中至少一轴量化差超过 1e-7；这项统计原样保留，**没有通过放宽原历史 oracle 获得通过**。原输入对原 oracle、量化后的相同输入对直接 Core 是两项独立检查，均通过。此次飞机位置参考变化为零，不代表后续真实闭环的位置误差为零。

## 查到并修复的接口问题

1. **同刻被误判成未来。** 新适配器最初将整数消息时间乘 `1e-9`，与十进制控制时间比较时产生几个 ULP 差。v2 的首批 400 行有 24 行被拒；改成整数比较后，v3 在导出 Core 的 double 时间边界仍出现同样 24 行失败。最终统一整数比较和秒值除法转换。42.284 s 相等时间回归通过；提前 1 ns 的控制时刻仍拒绝未来关节样本。没有增加延迟容忍量。
2. **ABI 数字相同不保证布局一致。** 当前开发头文件与已验证 NX 库对应的历史头文件不同，均标为 ABI 4。本次复用旧库并绑定其原始头文件；构建期检查头文件 SHA，运行前后检查库 SHA，并记录实际加载库。没有把当前开发头文件与历史库混用。

v1 是缺少 CDR 完整类型头文件的编译失败，已修复。v4 完整通过后，v5 增加逐轴量化记录和构建期头文件绑定检查，重新通过全部 1,281 行。初始失败日志仍在电脑原始目录，未覆盖。以上不能外推成所有历史实时性问题已解决。
