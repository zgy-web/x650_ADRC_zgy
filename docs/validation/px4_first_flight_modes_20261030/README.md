## 事件与修复

1. `initial_inventory_v1`：只读清单完整。
2. `apply_v1`：零次写入。脚本把正常的 `prediction_error` 字段误识别为错误关键字而停止；改为完整词匹配，并增加回归测试。
3. `apply_v2`：倾角、偏航两项读回通过；第三项上升速度写入后出现警告，脚本停止。原报告计数2只代表成功返回的调用，不能据此否认第三项已写入；后续独立回读确认实际上限已为1。
4. 固定源码说明：`MPC_Z_V_AUTO_UP` 大于上限时会被提交为上限，并产生限速告警；此联动项被前期清单遗漏。现场补读为1。控制台只捕获警告的开头，因此不能把完整警告文本称为现场捕获证据。
5. 用户撤回提案，`restore_v1` 按真实备份恢复三项，确认原108项清单无剩余差异。随后告知遗漏及默认值依据，用户选择自主上升值暂留1。
6. 原八项实时写入入口禁用，防止之后误用撤回的提案。保留离线流程测试和现场守卫供审计；恢复工具只允许这三项备份值和保存命令，不能写自主速度默认值。

定义与联动分别见固定版本 [自主速度参数](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/src/modules/mc_pos_control/multicopter_autonomous_params.c) 与 [参数约束实现](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/src/modules/mc_pos_control/MulticopterPositionControl.cpp)。自主上升的源码默认3 m/s是参考值，**不是实测原值**；手动与Offboard上升使用 `MPC_Z_VEL_MAX_UP`。
