# MPC 可调用接口与上层 NMPC 离线原型

日期：2026-10-27。新服务器容器 `autodl-container-75dd488416-64c15ffa`。本轮按用户确认的路线，先做相同速度执行接口的上层 NMPC，随后再做力矩级全身 NMPC。原 MPC 权重、模型、限位、求解库及 ROS 运行入口没有因本轮改动而替换；不继续整定大偏差工况。

**MPC 接口封装验证通过；NMPC 已有可编译、可重复调用的离线原型，尚未进入新物理闭环验收。** 受扰数据中 31 个输入未得到满足完整接受条件的候选，未删除或改为通过。

## 交付内容

- [`x650_mpc_controller_v1`](../../../control_packages/x650_mpc_controller_v1/README.md)：C++ `Controller`，提供 `reset / prepare / commit_published / discard`。调用成功和执行器消费是不同事件；提交不阻塞等待 ROS 往返。
- [`x650_nmpc_controller_v1`](../../../control_packages/x650_nmpc_controller_v1/README.md)：同一五维速度输入的有界重线性化原型，完整非线性六项目标接受逻辑，实际停止余量复核，独立离线总计时。执行状态与数值迭代状态分开。
- [`NMPC_IMPLEMENTATION_NOTES_20261027.md`](../../NMPC_IMPLEMENTATION_NOTES_20261027.md)：文献依据、模型层次、TS20 非光滑映射、以后力矩级 NMPC 的建模和执行差异。

新包复用的三个已验证库在容器核验中 SHA 全部相符；见 `new_container_checks.json`。MPC facade 不重新编译这些库。新原型使用同一 Core 生成局部 QP 候选，但每次用原生 TS20 实际预测 q/dq、完整姿态及 FK 重新计算非线性目标，不能把原局部 QP 目标直接作跨迭代比较。

## 验证范围与结果

最初 24 个真实输入快照仅覆盖 0.048–0.992 秒的初始化／保持段。随后复用已经完成来源绑定的全量 ABI 4 数据，扩展到原保持任务 711 个、原受扰快速八字任务 570 个调用快照。这 1,281 个快照逐个恢复原输入和原 Memory；它们没有以新 NMPC 指令驱动 Gazebo，因此不是连续 NMPC 闭环重放，也不能据此计算新 NMPC 飞行误差。

| 检查 | 保持记录 | 受扰记录 |
|---|---:|---:|
| 原任务时间覆盖 | 0.052–29.996 s | 0.052–24.004 s |
| 输入快照 | 711 | 570 |
| MPC facade 与直接原 Core 完全相同 | 711/711 | 570/570 |
| 对原历史输出最大绝对差 | 0 | 1.943×10⁻¹⁶ |

| NMPC 无可接受候选 | 0 | 31 |

| 新原型总耗时最大值 | 14.095 ms | 42.826 ms |
| 超过 40 ms／50 ms 的输入 | 0／0 | 1／0 |

MPC facade 的输出、组装矩阵、QP 解、计划、原生预测包络、prepare 前后 Memory 与提交后 Memory 都与直接调用相等。历史输出比较另外保留原记录容差，不能把 1.943×10⁻¹⁶ 写成严格为零。

NMPC 最多尝试 4 个局部候选。第一个通过候选建立基准，之后只有原生检查通过、真实停止余量通过、完整非线性目标下降的候选才能替换它。目标下降不是新飞行的误差下降；原目标不再下降、停止余量拒绝、达到尝试次数分别记录，均不表示达到非线性 KKT 收敛。

这些是每快照一次的新服务器墙钟测量，没有 CPU 绑核或热稳态资格声明。离线调查预算为 200 ms，原 Core 每次仍有 50 ms 上限；40 ms 是现行上层名义周期，50 ms 也不是 50 Hz 的下发周期。表格统计包括失败输入，未知计时为 0。**其中 1 次超过 40 ms，所以不能宣称整个 NMPC 已通过 25 Hz 在线时序验收。** 每个新结果明确标记 `approved_for_online_publication=false`。

原生测试：MPC 包 7/7 项、NMPC 包 2/2 项通过。NMPC 检查包含独立六项成本复算、首步 31 ms 后续 40 ms 的非均匀时域、非零姿态变化的 `Rdot*r` 末端速度、真实约束证据一致性、一次求解只形成一次候选状态变化、失败与预算耗尽时不修改调用方 Memory。

## 31 个拒绝是什么

它们全部在第一候选的实际停止余量复核中拒绝，发生于原记录约 7.456–7.800、14.392–15.444、19.720–21.136 秒的部分输入。判据是已有规划停止行在非线性预测上的直接复核：

\[
q_{j,\min}\le q_{j,i}+r_j\dot q_{j,i}\le q_{j,\max},\qquad
r_j=\frac{\bar u_j}{2\bar a_j}+\Delta t_{\max}+T_{hold}+T_{age}.
\]

旧 Core 的普通成功路径主要约束这项的线性近似，恢复分支另外检查实际预测值。新 NMPC 外层对每个接受候选都复核实际预测，因此不能只凭旧 Core 返回成功放行。31 例超出此停止余量不等式的量约为 3.77×10⁻⁵–2.17×10⁻³ rad；**这个量不是实际关节角已越限，也不是末端位置误差**。原关节角、0.42／0.32 rad/s 速度内界、节点间包络与 160 ms 保持检查保留，没有加松弛。

原型采用“先得到可行候选，再优化成本”的有限迭代：若首个候选不通过，当前调用拒绝，不用旧周期候选或虚构测量兜底。若后续候选失败，保留同一快照下此前已通过的候选；报告中这类停迭代也单列。因此 `stop_reasons` 的停止余量计数可能多于 31 个最终拒绝。此处不重新整定原 MPC；恢复可行性的进一步设计属于后续 NMPC 实现事项。

全量输入复用 [`orin_abi4_20261027`](../orin_abi4_20261027/README.md) 的准备结果，没有重新拟合或修改测量。全量 Memory 是原 LiveStart 加原成功输出的确定性重建，**不是每步直接录下的 Memory**；原始 CDR、输出、源代码有哈希绑定，当前 facade 数值回放再次验证它。启动 24 输入则来自原顺序 oracle 直接保存的 `memory_before`。

1,281 是原 worker 调用快照数，不等于实际执行命令数。末尾候选保留，例如 `wrench_000570` 在 24.004 秒、正式窗口外未执行，也纳入算法条件测试，不据此扩大物理计分窗口。原受扰物理实验峰值不达标的结论没有改变。
