# 上层 MPC 降频与连续执行验证（2026-10-26）

本次针对相邻两次区间约束修复各耗时约 29–34 ms、而旧指令墙钟有效期只有 50 ms 时发生的退出，建立独立的 `mpc25_dispatch50_v1` 时间配置。旧版本、旧实验及其失败结论保留。此配置不构成硬实时保证，也不是 TS20-50 在 24 V 和实际空中载荷下的硬件认证。

## 修改范围

| 项目 | 原配置 | 新配置 |
|---|---:|---:|
| 上层名义求解间隔 | 约 20 ms，受实际首次发送释放影响 | 至少 40 ms 墙钟，且必须已实际首次发送上一候选 |
| 连续指令输出 | 20 ms | 20 ms |
| 单次求解及 issue 到候选准入期限 | 50 ms | 50 ms |
| 候选从原始 issue 起算的墙钟有效期 | 50 ms | 160 ms |
| 从候选原始物理状态时刻起算的保持上限 | 旧配置行为 | 160 ms，独立于墙钟检查 |
| 最大真实模型更新间隔 | 50 ms | 100 ms |
| 状态墙钟新鲜度 | 25 ms | 25 ms |
| 每个关节的异步消费进度监督 | 40 ms | 40 ms |
| TS20 内部总线周期 | 5 ms | 5 ms |
| 预测节点 / 后续节点间隔 | 15 / 40 ms | 15 / 40 ms |
| 决策变量 / 松弛变量 | 75 / 0 | 75 / 0 |
| 关节速度预测内界 | 0.42 / 0.32 rad/s | 0.42 / 0.32 rad/s |

周期从每次实际准入时刻重新计时，迟到后不追赶补发求解。输入仍使用真实相邻 `control_time` 之差，不强行写成 40 ms。仅新配置允许 1e-10 s 的浮点减法误差；100 ms 加 1 ns 仍拒绝。新的求解开始依然要求上一候选已首次实际发送，避免控制器把未发送的计划当成执行历史；实际关节消费继续采用异步进度监督，不逐条等待完整往返。

160 / 100 ms 是本次实验的显式预算。它们覆盖 50 ms 求解、20 ms 输出相位以及通知延迟的组合，并通过实际记录验收；不是系统最坏调度延迟的证明。重复发送不会刷新候选的原始时间戳。物理时钟与墙钟分别检查，避免仿真快于墙钟时额外使用未经模型覆盖的保持时间。

## 模型与执行的一致性

核心 ABI 升为 4，优化器打包接口升为 2，组装数据具有显式版本标识，避免旧库误读新字段。新增 `command_hold_s`，默认 0.05 s，原默认数学路径保留；新配置显式为 0.16 s。

待执行期间的关节位置保护、停止余量及历史保留窗口使用同一保持时长。新的最终候选还额外以原始实测关节状态、真实历史 MIT 数据包和第一条关节速度指令，调用原生 TS20 模型预测持续保持到 0.16 s 的结果。检查包括积分参考位置、位置/速度内界、原生节点之间的包络，以及原始预测节点和总线生效时刻。该检查失败不会提交控制器 Memory。

这是给定 TS20 条件模型与包历史下的关节补充检查，不是对机体或末端保持 160 ms 的安全证明；不能解释为任意未知未来发送相位、任意载荷和硬件误差下的鲁棒不变集证明。该保持路径重新计算自身的连续区间包络，并保留原预测节点和 MIT 生效时刻。已有实际在途历史不改写为计划历史，实测状态不前移到虚构的发送时刻。在线物理年龄依据最新已收到的状态时刻，仍受状态采样与通信新鲜度影响。

## 验证顺序与复现入口

1. 隔离构建 native、gateway 和 ROS worker，执行边界与事务性测试。
2. 使用三个保留的 ABI-3 完整输入/Memory（含原区间修复边界），检查 ABI-4 默认配置的矩阵、预测、输出与 Memory 数值一致性。
3. 从原记录的静止准备段选择真实相隔至少 40 ms 的状态，明确重编号并重绑定新配置，保留物理状态和实际包历史；使用新的连续 Memory 参考结果，与实际 ROS worker 的完整输出和 CDR 对比。这只是软件回放，不算新飞行。
4. 以实际 PX4/Gazebo 反馈执行新的完整 30 s 末端保持；必须检查连续下发、关节实际消费、PX4 编码、退出、已降落停桨且 disarmed，以及参数恢复。
5. 仅在新末端保持验收通过后，以同一后端重新执行原 24 s 三段外扰。幅值、波形、轨迹和物理误差阈值不变。

软件准备入口是 `scripts/qualify_x650_multirate.py`。物理执行入口是 `simulations/x650_cpp_multirate_v1/launch.py`；先用 `--dry-run` 核对当前库、配置、源码与模型，再执行同一命令去掉该选项。独立审计入口是 `scripts/audit_x650_cpp_multirate.py`。所有输出目录必须新建，失败记录不覆盖，不把软件结果或部分窗口作为物理通过证据。

完整物理统计窗口为 41.772–71.772 s。起点处继续保持原始预流指令，首条 C++ 输出的 writer 观测时刻为起点后 56 ms，PX4 首次收到该新 PVA 为起点后 60 ms。报告单列这段交接，并给出新 PVA 接收至窗口结束的 29.940 s；没有把预流记录改标成 MPC 或移动时间戳。旧审计两次失败原件保留：第一次误将另一路 writer 最新状态观测当作物理下发时钟；第二次沿用了首条 MPC 指令必须在 50 ms 内出现的旧假设。修复只作用于独立的新频率审计，原始记录及旧审计没有被改写。

软件验证包括 19 项 C++ 测试、23 项新配置/审计 Python 测试、4 项后续观察时钟测试及 16 项绘图关联测试；[跨 ABI 记录比对](legacy_cross_version.json)保留了旧默认配置下三个完整输入/Memory 的数值一致性证据。每个新阶段另有 24 个真实记录状态的连续软件回放与实际 ROS worker 输出比对；这些不计作新物理实验。

### 原 24 s 三段外扰

[完整后验审计](wrench_audit.json)和[独立原始记录复核](independent_wrench_review.json)确认完整执行 48.136–72.136 s 的原定窗口。最终元数据在随后一个 4 ms 物理步结束窗口；第 570 次求解于任务 24.004 s 发起并在正常退出过程中完成，未作为实际执行候选计算。最终审计 `complete=true`、`integrity_and_execution_passed=true`、`recovery_performance_passed=true`，但 `passed=false`、`physical_acceptance=false`，原因是原峰值精度未通过。

本次没有时序/优化故障，但**仍未通过原定末端峰值精度门槛**，不应记作整项实验通过。

两个关节各 1199 条指令（含退出零指令）均能在完整物理日志中对应到真实消费。在线观测器有一次双关节消费未被逐条观察到，记录为 `SUPERSEDED_OR_UNOBSERVED`，并保留原回执缺项；这不等于证明该条指令未执行。[消费观测补充核查](consumption_observation_review.json)逐条对照原始计数器与速度值：dispatch 3062 对应的 counter 1424 在五行连续物理记录中存在，在线只在随后看到 1425。未伪造回执，也未把异步状态观测当作逐条电机 ACK。退出零指令、发送器释放、降落停桨及诊断参数恢复均完成。

这两次完整运行支持采用“上层名义 25 Hz＋连续 50 Hz 执行”继续研究；尚不构成最坏调度时延保证或 Orin NX 真机实时认证。下一步应在同一外扰条件下定位第一段峰值的机体/关节贡献、约束活动和预测残差，针对抗扰瞬态改进模型或控制器，并保留当前结果作为基线。
