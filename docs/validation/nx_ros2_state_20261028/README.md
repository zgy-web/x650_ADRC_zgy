# 真实 NX / Pixhawk ROS 2 状态通道记录

日期：2026-10-28。设备为 Orin NX 16GB、达妙载板、Pixhawk 6X Pro。连接是 NX USB 主机口到飞控 USB。软件部署、代码对应与复现命令见 [状态通道指南](../../NX_PX4_ROS2_STATE.md)。

结论：**基本 ROS 2 状态接收检查通过；位置闭环条件尚未满足。** 本阶段没有实际运动或控制输出。

## 保留的过程证据

1. 用户目录 Agent 2.4.2 和 PX4 1.17 消息包编译成功；七个消息定义与固定固件版本源码一致。
2. C++ 探针在 NX 编译成功，CTest 1/1 通过，包括三轴坐标/姿态组合、无效四元数及时间戳异常检查。
3. 首次 60 秒 DDS 测试失败：建立会话和 participant 后停留在时间同步初始化，七个状态话题计数均为零。额外 20 秒协议抓包中，双方持续交换时间同步请求/响应，未创建状态 datawriter。
4. 独立虚拟串口测试只运行 NX 上的同一 Agent，未打开实际飞控：30 次请求均收到回复，首字节等待 0.198–0.722 ms。它仅排查 Agent 接收处理，不代表真实 USB 延迟。
5. 用户重启飞控，确认 USB MAVLink 和未解锁状态后重新临时切换 DDS。时间同步通过，约 5.6 秒后开始创建状态话题；60 秒测试收到七类状态，核心话题接收成功。
6. 随后停止并重新启动 Agent，飞控继续使用临时 DDS。按事先选择的 15 秒初始化 + 60 秒统计窗口复查，完整窗口检查通过。

重启后成功、随后 Agent 重连也成功，说明通道已经具备基本可用性。**首次初始化卡住的底层原因尚未证实**；不能据此宣称 USB/飞控驱动缺陷已修复，也不能将约 11 ms 请求间隔直接当成 RTT。后续仍需多次冷启动、热插拔和长时间运行检查。本次没有关闭时间同步或修改飞控持久参数来绕过异常。

## 完整 60 秒窗口

统计源为 `dds_session_04_reconnect.jsonl`，从探针启动后第 15 秒至第 75 秒。接收间隔在 NX 本机单调时钟计时；源时间戳单独检查。

| 话题 | 数量 | 接收频率 | 最大回调接收间隔 |
|---|---:|---:|---:|
| VehicleAttitude | 6,000 | 99.995 Hz | 13.74 ms |
| VehicleLocalPosition v1 | 3,000 | 49.998 Hz | 23.82 ms |
| VehicleOdometry | 6,000 | 99.994 Hz | 12.54 ms |
| SensorCombined | 6,000 | 99.995 Hz | 13.80 ms |
| VehicleStatus v1 | 118 | 1.967 Hz | 513.39 ms |
| EstimatorStatusFlags | 59 | 0.994 Hz | 1,014.28 ms |
| TimesyncStatus | 60 | 0.991 Hz | 1,012.45 ms |

全部七类话题在窗口内没有源时间戳倒退、重复或零时间戳；核心状态在每次每秒报告时保持新鲜。后三项属于较低频状态，不与 100 Hz 数据使用相同频率判据。

时间同步 RTT 的每秒快照：最小 **368 µs**，中位 **612.5 µs**，最大 **1,041 µs**。这是抽样后的飞控同步 RTT；不包含 SSH 返回电脑的等待，不是单向通信延迟，不是 MPC 计算时间，也不是最大延迟保证。

## 状态有效性

- 姿态和机体系角速度收到有效数值；已实现并测试 NED→ENU、FRD→FLU 和姿态双坐标系变换。
- `xy_valid=false`、`v_xy_valid=false`，`heading_good_for_control=false`；EKF 的 `yaw_aligned=false`，未融合外部视觉位置/速度。
- 垂向有效标志为真。水平坐标即使显示数值，也不能用作已验收的位置反馈。
- 全程没有观察到解锁状态；HIL 关闭；程序没有控制发布器。

下一阶段应先接入实际动捕定位，验证坐标轴、尺度、源时间、EKF 有效标志和重置连续性，再开展不接管的 MPC 实际状态影子运行。正式控制还需要关节反馈、执行器协议和退出行为的单独验收。
